# Handoff packet templates

Read when you are about to delegate implementation. One packet = one agent =
one concern. Packets carry commands, not answers; compute the expected results
privately and keep them for review. Never put secrets in a packet.

## Execution venue

- Default: a fresh worktree (`~/hft_worktrees/<theme>`).
- When verification needs the built venv or the full test suite and a fresh
  worktree cannot run it: the main tree, with a strict file allowlist,
  before/after `git status --porcelain` plus content-hash snapshots, and a
  rollback you run (`git checkout -- <files>`, files must be clean at baseline).
  Never use the main tree when the user's own edits are in the blast radius.

## Short packet (Tier 1, or one file under ~30 changed lines, no design choice)

```
GOAL: <1-2 sentences> · TIER: 1 or small-2 · MODEL: <Haiku/Sonnet>
ALLOWED FILE(S): <exact paths>
CONSTRAINTS: <the 1-2 laws that apply>
VERIFICATION (run every command; paste output):
- <command> — expect clean IN FILES YOU CHANGED; failures in files you did not
  change = stop and report, do not fix
STOP AND ESCALATE if: a listed file is missing; the change grows beyond the
allowed files; anything is red outside your scope; git state differs from baseline.
REPORT: the four tables (changed files / commands run / not verified / blockers).
NO git commands. NO edits outside ALLOWED FILE(S).
```

A short packet that turns out multi-file or high-risk: stop and upgrade to the full one.

## Full packet (Tier 3, Do-NOT-Edit, multi-file, or any design choice)

```
GOAL: <1-3 sentences> · TASK TYPE · TIER · MODEL
BUDGET: <scope/time bound; exceeding it = stop and report>
BASELINE: branch <name>; expected `git status --porcelain`: <paste>;
  baseline facts: <e.g. "target test file: 19 passed / 1 skipped">
ALLOWED FILES: <exact paths>
OFF-LIMITS: <paste the Do-NOT-Edit list from AGENTS.md>
VENUE: <worktree | main tree + allowlist + snapshots + rollback>
GOTCHAS (pasted, applicable only): <entries from module_gotchas.md>
CONSTRAINTS: <laws that apply to these files>
PRECEDENCE: the general rule beats any enumerated list below. Enumerations
  were generated by: <paste the command>
VERIFICATION: <exact commands; each with the pre-existing-red escape hatch>
STOP AND ESCALATE if: a listed file is missing; anything touches prices, time,
  contracts, or events unexpectedly; the packet contradicts itself; budget exceeded.
ROLLBACK (orchestrator only): <command>
REPORT: four tables as the final message, even if you stall.
NO git commands. NO edits outside ALLOWED FILES.
```

Keep the whole packet near 150 lines; paste only the gotchas that apply.

## Independent review packet

A delegated review is a packet with three extra rules (two delivery failures
on record: an idle background reviewer, and ~734K tokens with no verdict):

1. Diff-scoped, never repo-scoped: name the exact diff (commit or range) and a
   small set of governing files. No open-ended "review the repo".
2. Delivery is part of the contract: a single review runs with
   `run_in_background: false`. If backgrounded, require delivery via
   SendMessage plus a hard tool budget, and state that a verdict is mandatory
   before the budget runs out (cut checks, not the verdict).
3. Silence is a failure, never an approval: with no verdict, do the review yourself.
